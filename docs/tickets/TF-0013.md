## Estado

## Tipo

FEATURE

## Prioridad

## Objetivo

Permitir marcar una tarea como completada desde la interfaz, con un botón por
tarea en la lista de pendientes, mediante una ruta POST protegida por el CSRF de
TF-0008.

## Diagnóstico

Promoción de **BL-04**, slice **a** de 3 (completar / editar / eliminar).

- `DBManager` solo tenía `crear_tarea`, `obtener_proyectos`, `obtener_tareas`;
  ninguna operación para cambiar el estado de una tarea.
- `Tarea.marcar_como_completada()` (`src/modelos.py`) existía pero solo lo usaban
  los tests.
- `app.py` exponía solo `GET /` y `GET|POST /crear`; `index()` lista solo
  `estado="Pendiente"`.
- Consecuencia: una tarea creada no podía cerrarse nunca desde la app.

## Cambios realizados

- **`src/database.py`**: `DBManager.marcar_tarea_completada(tarea_id) -> bool` —
  `UPDATE tareas SET estado='Completada' WHERE id=?`; devuelve `True` si actualizó
  una fila (`cursor.rowcount > 0`), `False` si el id no existe.
- **`app.py`**: ruta `POST /tareas/<int:tarea_id>/completar` → `completar_tarea`:
  `abort(404)` si `marcar_tarea_completada` devuelve `False`;
  `redirect(url_for('index'))` si OK. CSRF cubierto por `proteccion_csrf`
  (before_request de TF-0008).
- **`templates/index.html`**: en cada `task-card`, un `<form method="POST">` con
  `<input type="hidden" name="csrf_token" value="{{ csrf_token }}">` y botón
  "Completar".
- **`tests/test_database.py`**: `TestMarcarTareaCompletada` (3 tests).
- **`tests/test_app.py`**: 6 tests de la ruta (302 / 404 / 405 / 403 / id no
  numérico / desaparece de la lista).
- **`docs/BACKLOG.md`**: `BL-04` → `PROMOTED` / `TF-0013`, con el desglose de los
  3 slices.

**Sin cambios** en `src/modelos.py`, `src/seguridad.py`, `src/validaciones.py`,
`crear_tarea`, `obtener_tareas`, `Dockerfile`, CI ni requirements. Sin
dependencias nuevas. Se hace `UPDATE` directo por id (sin leer-modificar-escribir)
para evitar condición de carrera y no introducir `obtener_tarea(id)` fuera de
alcance.
