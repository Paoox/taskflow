# TF-0011 — Actualizar el runtime a Python 3.12

## Estado

DONE (verificado en Python 3.12 vía `python:3.12-slim` y en Docker. Pendiente de
confirmación externa: run real en GitHub Actions; recreación del venv local en
3.12 —no hay Python 3.12 en el host—).

## Tipo

SECURITY / DEVOPS

## Prioridad

P2

## Objetivo

Migrar el runtime de Taskflow de Python 3.8 (EOL, sin parches de seguridad desde
2024-10) a **Python 3.12** en la imagen Docker y en CI, y simplificar
`requirements.txt`, manteniendo la suite y el arranque verificados.

## Diagnóstico

- `Dockerfile`: `FROM python:3.8-slim`.
- `requirements.txt`: fijaba `importlib-metadata==8.5.0` y `zipp==3.20.2`. En
  Python 3.12 nadie las necesita: `flask` solo requiere `importlib-metadata` con
  marker `python_version < "3.10"` y `click` con `python_version < "3.8"`; tras
  instalar sin ellas, `pip check` queda limpio y `pip show importlib-metadata` →
  *Package(s) not found*.
- `requirements-dev.txt`: `pytest==8.3.5`, `pytest-cov==5.0.0`, `coverage==7.6.1`
  — **todas compatibles con Python 3.12** (verificado). No requieren bump.
- `.github/workflows/ci.yml`: `python-version: "3.8"`.
- Host de desarrollo: solo Python 3.8.10 (`/usr/bin/python3`); sin `pyenv`/`uv`/
  `conda`; sin Python 3.12 en repos de apt. Por eso la verificación en 3.12 se
  hace con el contenedor `python:3.12-slim` (Opción C aprobada por Pao).
- Red de seguridad: 90 tests, cobertura 94 %, CI verde (TF-0010).

## Cambios realizados

- **`Dockerfile`**: `FROM python:3.8-slim` → `FROM python:3.12-slim`; comentario de
  cabecera actualizado (motivo del cambio + nota de que la verificación se hizo
  con `python:3.12-slim` porque el host no tiene 3.12).
- **`requirements.txt`**: eliminadas las líneas `importlib-metadata==8.5.0` y
  `zipp==3.20.2`; comentarios actualizados ("Entorno verificado: Python 3.12";
  explicación del porqué de la eliminación). El resto de pines **sin cambios**
  (instalan limpio en 3.12).
- **`.github/workflows/ci.yml`**: `python-version: "3.8"` → `"3.12"`; nombre del
  step actualizado.
- **`docs/BACKLOG.md`**: `BL-07` → `PROMOTED`, `Ticket = TF-0011`; detalle
  ampliado.
- **`docs/tickets/TF-0011.md`**: este documento.

**Sin cambios en `app.py`, `src/*.py`, plantillas ni tests** (no apareció ninguna
incompatibilidad con Python 3.12). **Sin bumps de pins.** `requirements-dev.txt`
sin cambios.

## Riesgos

- **R1 (medio)** — Cambio de infra significativo (§31). Mitigado: verificado en
  3.12 (suite + `pip check`) y en Docker (build + endpoints + CSRF + persistencia)
  antes del commit.
- **R2 (no materializado)** — Ningún pin necesitó bump en 3.12; `requirements-dev.txt`
  intacto.
- **R3 (parcial, aceptado)** — Desfase local: el `venv/` del host sigue en 3.8
  porque no hay Python 3.12 instalable sin tocar el sistema (Opción C). La imagen
  y CI sí van a 3.12. Documentado como pendiente.
- **R4 (bajo)** — En Python 3.8, un `pip install` desde el nuevo `requirements.txt`
  ya no fija `importlib-metadata`/`zipp` a una versión concreta (Flask las
  arrastra por marker). Aceptable: 3.12 es ahora el entorno de referencia.
- **R5 (cerrado de paso)** — La imagen no se reconstruía desde antes de TF-0007/08;
  este ticket la reconstruye y re-verifica con `src/validaciones.py` y
  `src/seguridad.py` incluidos.
- **R6 (nulo)** — No toca lógica de negocio ni el esquema de datos.
