# TF-0003-01 — Contenedorización inicial con Docker

## Estado

DONE

## Tipo

DEVOPS

## Prioridad

No registrada formalmente.

## Objetivo

Estandarizar el entorno de ejecución con Docker, manteniendo la arquitectura de
un solo servicio:

```text
Docker → Flask → SQLite
```

conforme a la sección 25 de `CLAUDE.md`.

## Contexto

Primer uso de Docker en el proyecto. Pre-aprobado por `CLAUDE.md` §31 (Docker
como entorno de ejecución no requiere aprobación para su implementación inicial
si respeta §25).

Durante la implementación, el daemon de Docker no era accesible desde el entorno
WSL de trabajo. El `build` y el `run` los verificó Pao en su entorno WSL2.
Posteriormente el flujo se re-verificó al ejecutar TF-0003-02.

## Cambios realizados

- **`Dockerfile`** (nuevo):
  - Base `python:3.8-slim` (coincide con el entorno verificado en
    `requirements.txt`).
  - `ENV PYTHONDONTWRITEBYTECODE=1`, `PYTHONUNBUFFERED=1`, `FLASK_APP=app.py`,
    `TASKFLOW_DB=/app/data/tareas.db`.
  - `WORKDIR /app`; instalación de `requirements.txt`; `COPY . .`.
  - `RUN mkdir -p /app/data` y `VOLUME ["/app/data"]` para la persistencia de
    SQLite (§25.5).
  - `EXPOSE 5000`; `CMD ["flask", "run", "--host=0.0.0.0", "--port=5000"]`.
- **`.dockerignore`** (nuevo): excluye `venv/`, `__pycache__/`, `*.pyc`,
  `.git/`, `.gitignore`, `.dockerignore`, `Dockerfile`, `.idea/`, `.vscode/`,
  `.env`, `tareas.db`, `*.db`, `CLAUDE.md`, `.claude/`.
- **`.env.example`** (nuevo): documenta `TASKFLOW_DB` sin valores sensibles
  (§25.3).
- **`src/database.py`** (+3 / −1):
  `DATABASE_NAME = os.environ.get('TASKFLOW_DB', 'tareas.db')`. Ruta configurable
  por entorno para permitir montar un volumen en Docker; el valor por defecto
  conserva el comportamiento local previo.

## Pruebas

**Local (venv) — VERIFICADO:**

- Import de `app`; `GET /` y `GET /crear` = 200 con la base de datos por defecto.
- `TASKFLOW_DB` redirige el archivo SQLite a la ruta indicada; `GET /` = 200.
- `flask run --host=0.0.0.0` (mismo comando que el `CMD`) sirve en `0.0.0.0` y
  responde 200.

**Docker — VERIFICADO por Pao (entorno WSL2):**

- `docker build -t taskflow:dev .` → PASS.
- `docker run ...` → contenedor `taskflow-test` UP.
- Mapeo de puerto `0.0.0.0:5000->5000/tcp` → PASS.
- Interfaz accesible desde el navegador en `http://localhost:5000` → PASS.

## Criterios de aceptación

Formulación retroactiva sobre `CLAUDE.md` §25:

- La imagen construye de forma reproducible. — cumplido
- Un contenedor sirve Taskflow (Flask + SQLite) en el puerto 5000. — cumplido
- La aplicación no depende de paquetes instalados manualmente en el host. — cumplido
- `tareas.db` puede persistir en un volumen (`/app/data`) y no depende del
  filesystem efímero del contenedor (§25.5). — mecanismo provisto; verificado en
  profundidad en TF-0003-02.

## Decisiones y riesgos

- Base `python:3.8-slim` para coincidir con el entorno verificado (los pines de
  `importlib-metadata` / `zipp` asumen Python < 3.10). Un upgrade de Python sería
  un ticket aparte.
- Se usa el servidor de desarrollo de Flask (`flask run`); un servidor WSGI de
  producción se evaluará en un ticket posterior.
- Ruta de la base de datos por variable de entorno (`TASKFLOW_DB`): cambio mínimo
  y retrocompatible, justificado por §25.5.
- Riesgo bajo: `sqlite3.connect()` no crea directorios padre; cubierto por
  `mkdir -p /app/data` en la imagen y por el volumen montado.
