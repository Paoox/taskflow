## Estado

## Tipo

DEVOPS / TEST

## Objetivo

Ejecutar la suite `pytest` automáticamente en cada `push` y `pull_request` sobre
`main`, con reporte de cobertura (informativo, sin umbral), para que ninguna
regresión llegue a `main` sin detección.

## Contexto

Promoción de **BL-08** (`docs/BACKLOG.md`), re-priorizado a **P2** por su efecto
multiplicador sobre BL-04 (feature grande) y BL-07 (upgrade de Python).

Estado previo: 90 tests, cero automatización. Repo en GitHub
(`git@github.com:Paoox/taskflow.git`) sin `.github/`. Cada ticket se ha
verificado a mano con `python -m pytest`.

## Cambios realizados

- **`.github/workflows/ci.yml`** (nuevo): workflow `CI`.
  - Disparadores: `push` y `pull_request` sobre `main`.
  - Job `test` en `ubuntu-latest`: `actions/checkout@v4`,
    `actions/setup-python@v5` con `python-version: "3.8"`,
    `pip install -r requirements.txt -r requirements-dev.txt`, `python -m pytest`.
  - La clave `on` va entrecomillada (`"on":`) para evitar la interpretación como
    booleano de analizadores YAML 1.1; GitHub Actions acepta ambas formas.
- **`requirements-dev.txt`**: `+pytest-cov==5.0.0` (última serie compatible con
  Python 3.8; 6.x exige ≥ 3.9) y su transitiva `+coverage==7.6.1` (última que
  soporta 3.8), fijadas con `==`.
- **`pytest.ini`**: `addopts = --cov=src --cov=app --cov-report=term-missing`
  (cobertura **informativa**, sin `--cov-fail-under`).
- **`.gitignore`**: ignora `.coverage`, `.coverage.*`, `htmlcov/`, `coverage.xml`.
- **`.dockerignore`**: excluye `.github/` y los artefactos de cobertura de la
  imagen de runtime (coherente con la exclusión de `tests/` de TF-0005).
- **`docs/BACKLOG.md`**:
  - `BL-08` → `PROMOTED`, `Ticket = TF-0010`, prioridad `P2`; texto de detalle
    actualizado (23 → 90 tests) y resumen de la solución.
  - Alta de **`BL-13`** (`OPEN`, `SECURITY/DEVOPS`, `P2`): el contenedor arranca
    con clave de sesión efímera porque el `Dockerfile` no define
    `TASKFLOW_SECRET_KEY`; incluye la nota sobre `SESSION_COOKIE_SECURE` para
    despliegue tras TLS.

**Sin cambios en código de aplicación ni de tests.** Sin Docker en CI. Sin
servicios externos de cobertura.

## Decisiones y riesgos

- **GitHub Actions**, `pytest` + `pytest-cov`, cobertura informativa sin umbral,
  **solo Python 3.8**, disparadores `push` + `pull_request` sobre `main` — todo
  según la especificación aprobada por Pao.
- Sin Docker en CI, sin servicios externos de cobertura — aprobado.
- `BL-13` registrado como `OPEN`/`P2`; `BL-14` (páginas de error con estilo)
  queda fuera — aprobado.
- Se añadieron `.coverage*` a `.gitignore` (necesario: `pytest-cov` crea
  `.coverage` en la raíz) y a `.dockerignore` junto con `.github/` (higiene de
  imagen, mismo criterio que TF-0005). Reversible si se objeta.
- **R1 (bajo)** — `pytest-cov`/`coverage` como nuevas deps de desarrollo (§23).
  Justificadas por §19/§20/§35. Solo dev, no runtime.
- **R2 (medio, no verificable aquí)** — El primer run en Actions podría fallar por
  detalles del entorno CI (`pythonpath`, locale, permisos de `tmp_path`).
  Mitigación: `conftest.py` ya aísla la DB por `tmp_path`; la config es mínima. Se
  corrige en un follow-up acotado si ocurre.
- **R3 (bajo)** — `actions/*@vN` son tags móviles. Alternativa: SHA-pin (más
  reproducible, más mantenimiento).
- **R4 (bajo)** — Python 3.8 en `setup-python`: EOL pero aún disponible en
  Actions; alineado a propósito con el entorno actual. BL-07 lo actualizará.
- **R5 (nulo)** — No toca lógica de negocio.
