# TF-0004 — Documentación persistente de tickets

## Estado

DONE

## Tipo

DOCS

## Prioridad

P1

## Objetivo

Crear un mecanismo simple y persistente dentro del repositorio para documentar
cada ticket de desarrollo, de forma que el historial de decisiones, cambios,
pruebas y criterios de aceptación no dependa exclusivamente de las conversaciones
con Claude. La documentación vive en Git junto al código.

## Contexto

Hasta ahora el trabajo por ticket solo quedaba registrado en:

- mensajes de commit (`TF-XXXX: ...`),
- comentarios con ID de ticket en los archivos tocados,
- reportes generados en el chat (no persistidos en el repo).

No existía `docs/`, `TICKETS.md`, `CHANGELOG.md`, `README` ni `.github/`.

## Cambios realizados

- Nuevo directorio `docs/tickets/`.
- Nuevos documentos de los tickets ya completados:
  - `docs/tickets/TF-0001.md` (reconstruido retroactivamente desde Git; sesión
    original no disponible).
  - `docs/tickets/TF-0002.md` (reconstruido desde Git + mensaje de commit).
  - `docs/tickets/TF-0003-01.md` (sesión actual; datos completos).
  - `docs/tickets/TF-0003-02.md` (sesión actual; datos completos).
- Este documento, `docs/tickets/TF-0004.md`.
- `CLAUDE.md`: nueva subsección **29.1 Documentación persistente de tickets**,
  integrada dentro de la sección 29 (Documentación). No se modifica ninguna otra
  regla. Establece que:
  1. Todo ticket debe tener un documento en `docs/tickets/TF-XXXX.md`.
  2. Un ticket no se marca `DONE` hasta que su documento esté creado y
     actualizado.
  3. Cada documento registra objetivo, contexto, cambios, archivos afectados,
     pruebas, criterios de aceptación y commit (SHA + mensaje) cuando exista.
  4. La documentación en `docs/tickets/` es la fuente de verdad histórica del
     ticket; la conversación con Claude no es el único registro.
  5. Los reportes de ejecución deben poder trasladarse al documento sin perder
     información relevante.

## Decisiones y riesgos

- Se añadió también `docs/tickets/TF-0004.md` (este archivo), que va más allá de
  la lista literal de CA-02 (cuatro documentos), porque la propia regla 29.1 que
  introduce el ticket exige que *todo* ticket tenga documento y que no se marque
  `DONE` sin él. Pao puede vetar este archivo.
- La regla se integró como subsección **29.1** en lugar de una sección nueva
  numerada, para no renumerar las secciones 30–35 de `CLAUDE.md`.
- Los documentos de TF-0001 y TF-0002 son retroactivos: las secciones de pruebas
  y decisiones indican explícitamente lo que "no consta", sin inventar.
